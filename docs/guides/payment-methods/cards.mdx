# Save Cards

A saved card has an `id` that starts with `card_`. You use it to create payments and payouts, and to charge the customer later. Save a card in one of two ways:

- **Credova Elements** captures the card in your web app. Card data never touches your servers, so you avoid PCI requirements.
- **The Direct API** posts the card from your servers. Your organization must be PCI certified.

## Storing Cards

Now that you are capturing cardholder data in your web application, it is time to store the card in your account.

To do this, we will call the `create card` method from the SDK, passing the Card Elements as data points in the payload.

Add a submit function along with a button to trigger it:

```javascript showLineNumbers title="index.js"
async function init () {
  ...
  //highlight-next-line
  document.getElementById("submit").addEventListener("click", submit);
}

// highlight-start
async function submit (e: FormEvent<HTMLFormElement>,) {
  try {
    const formData = new FormData(e.currentTarget)

    const card = await publicsquare.cards.create({
      cardholder_name: formData.cardholderName,
      card: {
        number: cardNumberElement,
        expirationMonth: cardExpirationDateElement.month(),
        expirationYear: cardExpirationDateElement.year(),
        cvc: cardVerificationCodeElement,
      }
    });
    // store card.id in your database
  } catch (error) {
    console.error(error);
  }
}
// highlight-end

init();
```

## Save a Card

Send the card in a `POST` request to `https://collect.publicsquare.com`:

```shell showLineNumbers
curl -L 'https://collect.publicsquare.com' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'X-API-KEY: <PUBLISHABLE_API_KEY>' \
-d '{
  "cardholder_name": "John Smith",
  "card": {
    "number": "4242424242424242",
    "expiration_month": 12,
    "expiration_year": 2030,
    "cvc": "123"
  }
}'

```

The request body accepts these fields:

| Field | Required | Description |
|-------|----------|-------------|
| `cardholder_name` | Yes | Name on the card. |
| `card.number` | Yes | Card number. |
| `card.expiration_month` | Yes | Expiration month, from `1` to `12`. |
| `card.expiration_year` | Yes | Four-digit expiration year. The expiration date must be in the future. |
| `card.cvc` | No | Card security code. If you send it, PublicSquare still validates it. |
| `customer_id` | No | ID of an existing customer to associate with the card. |
| `billing_details` | No | Billing address for the card. |

## Saving a card without a CVC

The `cvc` field is optional. Leave it out when you save a card that you will charge later without the customer present, for example a card on file or a card that you move from another vault.

<Alert type="warning">A card saved without a CVC can decline more often on its first charge. Its `cvv2_reply` cannot show a match (`M`), so do not use a missing CVV as a reason to decline these payments. See [Fraud Details and Prevention](/concepts/fraud-details-and-prevention#card-verification-value-cvv).</Alert>

```shell showLineNumbers
curl -L 'https://collect.publicsquare.com' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'X-API-KEY: <PUBLISHABLE_API_KEY>' \
-d '{
  "cardholder_name": "John Smith",
  "card": {
    "number": "4242424242424242",
    "expiration_month": 12,
    "expiration_year": 2030
  }
}'

```
