# Accept Card Payments

In this guide, we will create a payment with a card from your server. The card is either already saved, or it arrives in the payment request.

- **Saved card**: collect and save the card first with [Save Cards](/guides/payment-methods/cards). Then create the payment with Payment Intents or the Payments API.
- **Card details in the request**: your servers send the card in the payment request. Your organization must be PCI certified.

## Creating a Payment

Use the `id` of a [saved card](/guides/payment-methods/cards) and create the payment from your server using your `Secret Key`.

You can create card payments using either Payment Intents or the direct Payments API. Both approaches result in a `Payment` object. We recommend Payment Intents for new integrations. They keep state across the whole lifecycle, report slow outcomes by webhook and retry safely.

<Tabs className="publicsquare-tabs" groupId="api-style" queryString="api">
  <TabItem value="payment-intents" label="Payment Intents" default>

A Payment Intent represents your intent to collect funds from a customer. It tracks the full lifecycle of a charge — creation, confirmation, processing, and the final `succeeded` state — and creates a `Payment` record on success.

### Create a Payment Intent

Call the [Create Payment Intent](/api/financial/create-payment-intent) endpoint. Including a card at creation time starts the intent in `requires_confirmation` status and it is ready to confirm immediately:

```shell showLineNumbers title="Create a Payment Intent"
curl 'https://api.publicsquare.com/payment_intents' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "capture_method": "automatic",
  "payment_method": {
    "card": "card_AjkCFKAYiTsjghXWMzoXFPMxj"
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

<Alert>The amount is provided in cents. 1000 is the equivalent of $10.00</Alert>

<Alert type="warning">The IDEMPOTENCY-KEY header can be passed to protect against duplicate payment intents being created.</Alert>

```json showLineNumbers title="Create Response"

  "id": "pmt_int_2xNjK7abcdefghij",

  "status": "requires_confirmation",
  "amount": 1000,
  "currency": "USD",

  "payment_method": {
    "card": {

  "created_date": "2026-04-15T14:22:10Z",

```

### Create Without a Payment Method

For multi-step checkout flows where the payment method is collected separately, omit the `payment_method` field. The intent starts in `requires_payment_method` status and the amount and other details can still be updated before a card is attached:

```shell showLineNumbers title="Create a Payment Intent without a Payment Method"
curl 'https://api.publicsquare.com/payment_intents' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "capture_method": "automatic"
}'
```

```json showLineNumbers title="Create Response"
{
  "id": "pmt_int_2xNjK7abcdefghij",
  "account_id": "acc_B518niGwGYKzig6vtrRVZGGGV",
  "environment": "test",
  // highlight-next-line
  "status": "requires_payment_method",
  "amount": 1000,
  "currency": "USD",
  "capture_method": "automatic",

  "created_date": "2026-04-15T14:22:10Z",
```

Once you have a card, call the [Update Payment Intent](/api/financial/update-payment-intent) endpoint to attach it. The intent will transition to `requires_confirmation`:

```shell showLineNumbers title="Attach a Payment Method"
curl 'https://api.publicsquare.com/payment_intents/pmt_int_2xNjK7abcdefghij' \
-X 'PUT' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'Content-Type: application/json' \
-d '{
  "payment_method": {
    "card": "card_AjkCFKAYiTsjghXWMzoXFPMxj"
  }
}'
```

### Confirm the Payment Intent

With the intent in `requires_confirmation`, call the [Confirm Payment Intent](/api/financial/confirm-payment-intent) endpoint to submit the charge to the processor:

```shell showLineNumbers title="Confirm a Payment Intent"
curl 'https://api.publicsquare.com/payment_intents/pmt_int_2xNjK7abcdefghij/confirm' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 3a9f1b72-cc4e-4f92-b7d3-1e5a9c8d2041' \
-H 'Content-Type: application/json'
```

When the processor responds quickly, you will receive a `200` with `status: succeeded` and a populated `payment_id`:

```json showLineNumbers title="Confirm Response — Succeeded (200)"
{
  "id": "pmt_int_2xNjK7abcdefghij",
  "account_id": "acc_B518niGwGYKzig6vtrRVZGGGV",
  "environment": "test",
  // highlight-next-line
  "status": "succeeded",
  "amount": 1000,
  "currency": "USD",
  // highlight-next-line
  "payment_id": "pmt_5mBpT2ghiklmnopq",
  "next_action": null,
  "expires_date": null,
  "succeeded_date": "2026-04-15T14:22:45Z",
  "created_date": "2026-04-15T14:22:10Z",
  "modified_date": "2026-04-15T14:22:45Z"
}
```

When the processor takes longer to respond, you will receive a `202` with `status: processing`:

```json showLineNumbers title="Confirm Response — Processing (202)"
{
  "id": "pmt_int_2xNjK7abcdefghij",
  "account_id": "acc_B518niGwGYKzig6vtrRVZGGGV",

  "status": "processing",
  "amount": 1000,
  "currency": "USD",
  "payment_id": null,

  "created_date": "2026-04-15T14:22:10Z",
  "modified_date": "2026-04-15T14:22:35Z"
```


### Handling Declines

If the card is hard-declined, the intent returns to `requires_confirmation` and the `last_payment_error` field is populated with the decline reason. You can attach a new payment method and re-confirm the same intent — no need to create a new one:

```json showLineNumbers title="Declined Payment Intent"
{
  "id": "pmt_int_2xNjK7abcdefghij",
  // highlight-next-line
  "status": "requires_confirmation",
  // highlight-next-line
  "last_payment_error": {
    "code": "card_declined",
    "message": "Your card was declined."
  },
  ...
}
```

<h3 id="create-a-payment">Create a Payment</h3>

```shell showLineNumbers title="Create a Payment"
-X 'POST' \

-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "card": "card_AjkCFKAYiTsjghXWMzoXFPMxj"

  "customer": {

}'
```

The amount is in cents. `1000` is $10.00.

<Alert type="warning">Your servers receive and send cardholder data in this flow, so your organization must be PCI certified. If you are unsure, please [contact support](/support). To keep card data out of your servers, [save the card with Credova Elements](/guides/payment-methods/cards) and use the Saved card tab.</Alert>

Send the card details in the same request that creates the payment. You do not need to save the card first. The API saves the card to the customer and returns its `id` for later payments.

<Alert>We recommend [Payment Intents](/concepts/payment-intents) for new integrations. They retry safely and report slow processors by webhook. Payment Intents do not accept `card_details`, so use the Saved card tab to create an intent with the card `id`. Use `card_details` with [Create Payment](/api/financial/create-payment) when you want to send the card and charge it in one request.</Alert>

A restricted key needs the `payment-method:write` or `payment-method:capture` permission, in addition to the permission to create payments.

To send a payout with card details, see [Send Card Payouts](/guides/payouts/process-card-payouts).

## Process a Payment

A payment with `card_details` also needs `device_information.ip_address`, the IP address of the customer's device.

### Create a Payment with Card Details

```shell showLineNumbers title="Create a Payment with Card Details"
curl 'https://secure.payments.credova.com/payments' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    // highlight-start
    "card_details": {
      "cardholder_name": "John Smith",
      "number": "4242424242424242",
      "expiration_month": 12,
      "expiration_year": 2030,
      "cvc": "123"
    }
    // highlight-end
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  },
  "device_information": {
    "ip_address": "203.0.113.10"
  }
}'
```

<Alert>The amount is provided in cents. 1000 is the equivalent of $10.00</Alert>

To test, send the same request to `https://secure.payments.sbx.credova.com` with your test mode `Secret Key` and a [test card](/guides/testing#cards).
