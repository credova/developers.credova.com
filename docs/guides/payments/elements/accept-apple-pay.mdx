# Accept Apple Pay

In this guide, we will set up Credova Elements SDKs to capture Apple Pay in a frontend application and securely authorize and store the Apple Pay data while avoiding PCI requirements. Then we will create a payment with the collected Apple Pay payment method.

## Before you start

<BeforeYouStart keys={["publishable", "secret"]} />

### Domain Verification

Domain verification is a key step in getting Apple Pay up and running on your site. It is a required step for development and production servers, to confirm that you own the domain where Apple Pay will be implemented, preventing unauthorized use and maintaining the integrity of the payment system.

1. Serve the domain association file on your server at `https://<YOUR_DOMAIN>/.well-known/apple-developer-merchantid-domain-association` by proxying that path to the [domain association endpoint](#retrieve-the-domain-association-file) and returning the response as-is.
2. Add the public domain to your tenant using the [merchant portal](https://portal.publicsquare.com/settings/apple-pay) or the [API](/api/financial/register-apple-pay-domain)

Apple requires your website to use HTTPS. For local development, use a tunnel to get an HTTPS URL. [Cloudflare tunnel](https://developers.cloudflare.com/pages/how-to/preview-with-cloudflare-tunnel/) is one option.

#### Retrieve the domain association file

The API serves the Apple-issued domain association file for your account, so you no longer need to download and host a static copy yourself. Instead, have your server fetch it and return it at the well-known path Apple expects:

`GET https://api.publicsquare.com/.well-known/apple-developer-merchantid-domain-association`

**Authentication**: Requires an API key with the `payment-method:capture` permission, sent in the `X-API-KEY` header. Your [Publishable Key](#before-you-start) already has this permission, so no additional key is needed.

```shell showLineNumbers title="Retrieve the domain association file"
curl "https://api.publicsquare.com/.well-known/apple-developer-merchantid-domain-association" \
  -H "X-API-KEY: <PUBLISHABLE_API_KEY>"
```

The returned file is processor-specific: the API automatically returns the domain association file matching whichever processor is currently set as your account's default processor, so you don't need to specify one.

| Status | Description |
| --- | --- |
| `200` | Returns the domain association file contents (`Content-Type: text/plain`) for your account's default processor. |
| `404` | No domain association file is configured for your account's default processor. Contact support if you believe this is unexpected. |

Proxy this request. Do not cache a static copy of the file. If your account's default processor changes, the endpoint returns the new file automatically.

## Billing and Shipping Addresses

<Alert>This behavior requires Credova Elements SDKs v1.15.2 or later.</Alert>

Apple Pay should always collect a billing address and phone number from the customer &mdash; this is required to create the payment method.

Set `requiredBillingContactFields: ['postalAddress', 'phone']` on the Apple Pay payment request passed to `ApplePaySession`, as shown in the [Configure Apple Pay](#configure-apple-pay) step above. When the customer authorizes the payment, Apple returns this information as `event.payment.billingContact`, and is automatically stored as the payment method's billing_details when you create the payment method.

Apple Pay collects the billing address in its FULL format, meaning customers see and enter a complete street address (not just a postal code), along with a billing phone number, and is stored on the payment method.

Shipping address collection is optional and off by default. Enable it with the `requiredShippingContactFields` option on the same payment request:

| Option | Type | Default | Description |
|--------|------|---------|--------------|
| `requiredBillingContactFields` | `ApplePayContactField[]` | *(required)* | Must include `'postalAddress'` and `'phone'`. Apple Pay always collects a billing address and phone number. Optionally `'phone'`, `'name'` and/or `'email'`. |
| `requiredShippingContactFields` | `ApplePayContactField[]` | `undefined` | When set, the Apple Pay sheet also collects a shipping address. Include `'postalAddress'` to collect the address, and optionally `'phone'`, `'name'` and/or `'email'`. |

When `requiredShippingContactFields` is set, the shipping address is returned as `event.payment.shippingContact`. We don't store the shipping address on the payment method, pass it along as `shipping_address` when you [create the payment](#create-a-payment). The billing address is already stored on the payment method from the earlier tokenization step, so you don't need to read it again here.

```javascript showLineNumbers title="index.js"
session.onpaymentauthorized = async (event: any) => {
  // highlight-start
  const shippingContact = event.payment.shippingContact;

  const shippingAddressPayload = shippingContact && {
    address_line_1: shippingContact.addressLines?.[0],
    address_line_2: shippingContact.addressLines?.[1],
    city: shippingContact.locality,
    state: shippingContact.administrativeArea,
    postal_code: shippingContact.postalCode,
    country: shippingContact.countryCode
  };
  // highlight-end

  const paymentMethod = await createApplePayPaymentMethod(event);
  session.completePayment(ApplePaySession.STATUS_SUCCESS);

  await chargePayment(paymentMethod.id, {
    // highlight-start
    shipping_address: shippingAddressPayload
    // highlight-end
  });
};
```

## Tokenization and Storing Apple Pay

After the customer has authorized the payment, your application will need to call our `create` method from the SDK with the encrypted Apple Pay token to create an Apple Pay payment method in your account.

To do this, we will handle the `session.onpaymentauthorized` event to call Public Square, passing the Apple Pay payment data:

  <TabItem value="javascript" label="JavaScript">
```javascript showLineNumbers title="index.js"
import { PublicSquare } from "@publicsquare/elements-js"

declare global {
  var ApplePaySession: any;
}

let publicsquare;

async function init() {
  publicsquare = await new PublicSquare().init('<PUBLISHABLE_API_KEY>');

   publicsquare.applePay.renderButton(buttonContainerRef.current!, {
    id: 'apple-pay-btn',
    onClick: onSubmitApplePay
  });

  function onSubmitApplePay() {
    if (!ApplePaySession) {
      return;
    }

    const session = createApplePaySession();

    session.onvalidatemerchant = async () =>{ ... };

    // highlight-start
    session.onpaymentauthorized = async (event: any) => {
      try {
        // Create an Apple Pay payment method from the encrypted payment token
        const paymentMethod = await createApplePayPaymentMethod(event);

        // Present green check to the user before the timeout (30 seconds)
        session.completePayment(ApplePaySession.STATUS_SUCCESS);

        // Send the payment method to the backend for payment processing
        await chargePayment(paymentMethod.id);
      } catch (e) {
        console.error(e);
        session.completePayment(ApplePaySession.STATUS_FAILURE);
      }
    };
    // highlight-end

    session.begin();
  }

  function createApplePaySession() { ... }

  async function validateMerchant() { ... }

  // highlight-start
  async function createApplePayPaymentMethod(event: any) {
    if (publicsquare) {
      try {
        const response = await publicsquare.applePay.create({
          apple_payment_data: event.payment,
        });
        if (response) {
          return response;
        }
      } catch (error) {
        console.log(error);
      }
    }
  }
  // highlight-end
}

await init();
```

## Process the Payment

Now that you have collected an Apple Pay payment method, use its `id` to create a payment. Your frontend sends the `id` to your backend, as in the `chargePayment` call above, and your backend makes the call with your [Secret Key](#before-you-start).

For example, given the Apple Pay payment method `appl_Aw3U2eESBnq6DoYEFn8qaSMrA` from the previous step:

### Create a Payment

We need to make a call to [Create Payment](/api/financial/create-payment) endpoint:

```shell showLineNumbers title="Create a Payment"
curl 'https://api.publicsquare.com/payments' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "apple_pay": "appl_Aw3U2eESBnq6DoYEFn8qaSMrA"
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

<Alert>The amount is provided in cents. 1000 is the equivalent of $10.00</Alert>

<Alert type="warning">The IDEMPOTENCY-KEY header can be passed to protect against duplicate payments being processed.</Alert>
