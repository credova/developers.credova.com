# Accept Bank Account Payments

In this guide, we will set up Credova Elements SDKs to capture bank accounts in a frontend application, securely authorize and store the bank account data while avoiding PCI requirements, and then process an ACH payment with the collected bank account.

## Before you start

<BeforeYouStart keys={["publishable", "secret"]} />

## Request Account Setting Access

Each way to collect a bank account needs an account setting. Request the setting for the option you plan to use:

- **Manual Entry** needs the `payment-methods:bank-accounts:manual-creation` account setting type. In the merchant portal, it is the `Manual Bank Account Creation` setting.
- **Instant Verification** needs the `payment-methods:bank-accounts:verification` account setting type. In the merchant portal, it is the `Bank Account Verification` setting.

To request a setting, go to the [merchant portal](https://portal.publicsquare.com/settings/features) and click the `Request this feature` button next to it.
Alternatively, you can request access via the [API](/api/accounts/request-account-setting-access).

Your account needs the setting before manual bank account creation or instant bank account verification works.

The `payment-methods:bank-accounts:manual-creation` setting also lets you send bank account details when you [process an ACH payment](#create-with-bank-account-details) or [an ACH payout](/guides/payouts/process-ach-payouts#create-with-bank-account-details). You do not need to create the bank account first.

## Collect the Bank Account

Credova Elements gives you two ways to collect a bank account:

- [Manual Entry](#manual-entry): your customer types the routing number and account number into the Bank Account Elements.
- [Instant Verification](#instant-verification): your customer connects their bank account and Credova verifies it instantly.

With either option, you create a `bank account` that holds the non-sensitive information about the bank account. You can safely store the bank account's `id` value in your database to link it with the appropriate payment or customer association.

When you create the bank account, you can optionally pass in a `customer_id` to associate with an existing [Created Customer](/api/accounts/create-customer) and `billing_details` to remove the requirement to pass them when [Creating a Payment](/api/financial/create-payment).

### Manual Entry

Manual entry captures the routing number and account number in your frontend application and stores them securely in your account.

#### Storing Bank Accounts

Now that you are capturing bank account data in your web application, it is time to store the bank account in your account.

To do this, we will call the `create bank account` method from the SDK, passing the Bank Account Elements as data points in the payload.

Add a submit function along with a button to trigger it:

<Tabs className="publicsquare-tabs" queryString="sdk">
  <TabItem value="javascript" label="JavaScript">
```javascript showLineNumbers title=index.js
async function submit (e: FormEvent<HTMLFormElement>,) {
  try {
    const formData = new FormData(e.currentTarget)
    const account_holder_name = formData.get('accountHolderName');
    const routing_number = bankAccountElement.routingNumber.el.value
    const account_number = bankAccountElement.accountNumber.el.value
    // highlight-start
    const bankAccount = await publicsquare.bankAccounts.create({
      account_holder_name,
      routing_number,
      account_number,
    });
    // highlight-end
    console.log(bankAccount); // e.g { id: 'ba_1234567890', ... }
  } catch (error) {
    console.error(error);
  }
}
```

### Instant Verification

Instant verification lets your customer connect their bank account so that Credova can verify it instantly, then stores the verified bank account in your account.

Credova has partnered with [Flinks](https://www.flinks.com/) to provide a secure way to collect bank accounts.
Once installed and configured, add the Bank Account Verification Elements to your application.

#### Nightly Balance Refresh

We automatically refresh the balance for all verified bank accounts for up to 30 days after verification. 
To obtain the most recent balance, you can make a call to the [Get Bank Account Balance](/api/financial/get-bank-account-balance-by-id) endpoint.

If more than 30 days have passed since the account was verified, you must re-verify the bank account to update its balance.

<Alert type="warning">Bank accounts with MFA enabled do not support nightly balance refresh.</Alert>

## Process the Payment

We will need to use the information from the previously [manually collected bank account](#manual-entry) or [collected verified bank account](#instant-verification) to create a new payment.

Use the `id` of the collected bank account, such as `ba_7Ay5mcUXAxwrN6wQEQUVEHBCJ`, as the `bank_account` value in the payment.

### Create a Payment

We need to make a call to [Create Payment](/api/financial/create-payment) endpoint:

```shell showLineNumbers title="Create a Payment"
curl 'https://api.publicsquare.com/payments' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "bank_account": "ba_7Ay5mcUXAxwrN6wQEQUVEHBCJ"
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

<Alert>The amount is provided in cents. 1000 is the equivalent of $10.00</Alert>

<Alert type="warning">The IDEMPOTENCY-KEY header can be passed to protect against duplicate payments being processed.</Alert>

### Create with Bank Account Details

If you have not saved the bank account yet, you can send its details with the payment. The API saves the bank account and charges it in the same request, so you do not need to call [Create Bank Account](/api/financial/create-bank-account) first.

Before you use `bank_account_details`:

- Your account must have the `payment-methods:bank-accounts:manual-creation` account setting. See [Request Account Setting Access](#request-account-setting-access).
- A restricted API key must have the `payment-method:write` permission in addition to `payment:write`. Secret keys have all permissions.

```shell showLineNumbers title="Create a Payment with Bank Account Details"
curl 'https://api.publicsquare.com/payments' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "bank_account_details": {
      "account_holder_name": "John Doe",
      "account_holder_type": "individual",
      "account_type": "checking",
      "routing_number": "110000000",
      "account_number": "000123456789"
    }
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

- `bank_account_details` accepts the same fields as [Create Bank Account](/api/financial/create-bank-account).
- Include `account_holder_name` and `account_holder_type`. Some processors require them.
- You cannot combine `bank_account_details` with `bank_account`, `card`, `apple_pay`, or `google_pay`.
- If you omit the top-level `customer` or `billing_details`, the payment uses the `customer_id` and `billing_details` inside `bank_account_details`.
- The response returns the saved bank account in `payment_method.bank_account`. Use its `id` as `bank_account` for later payments.
- [Payment intents](/concepts/payment-intents) accept `bank_account_details` when you create the intent. An update request with `bank_account_details` returns a 400.

<Alert type="warning">
  Send an `IDEMPOTENCY-KEY` with each request. If a request fails and you retry it with the same key, the payment uses the bank account that the first
  request saved. A retry with the same key and different bank account details returns a 400. Use a new key when you change the bank account details.
</Alert>

```json showLineNumbers title="Retry with different bank account details"
{
  "title": "Error",
  "status": 400,
  "detail": "'bank_account_details' differs from the request first sent with this IDEMPOTENCY-KEY."
}
```

## Payment Status

ACH payments do not settle instantly. A new ACH payment has the `pending` status. When the bank transfer settles, the payment moves to `succeeded`.
Subscribe to the [`payment:update` webhook](/concepts/webhooks) to receive each status change.

If the bank rejects the debit, the payment moves to `declined`. The `declined_reason` field contains the ACH return code and its description:

```json showLineNumbers title="Declined ACH payment"
{
  "id": "pmt_2YKewBonG4tgk12MheY3PiHDy",
  "status": "declined",
  "declined_reason": "R02 - Account Closed"
}
```

Some return codes also change the bank account's `status` to `closed` or `invalid`. A new payment with that bank account returns a 400 with
`bank account has 'closed' status.` See [Bank Accounts](/concepts/bank-accounts#statuses), and collect a new bank account from the customer.

You can [refund](/guides/refunds/refund-payments) an ACH payment after it reaches `succeeded`.
