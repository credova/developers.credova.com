# Send Bank Account Payouts

Let's send a payout to a bank account over the ACH network or real-time payment rails.

You need a saved bank account for this guide. Save one from your web app with [Accept Bank Account Payments](/guides/payments/elements/accept-bank-account-payments), or from your servers with [Save Bank Accounts](/guides/payments/direct-api/save-bank-accounts). Either way you get a bank account `id` that starts with `ba_`.

You can also skip saving the bank account and send its details in the payout request. See [Create with Bank Account Details](#create-with-bank-account-details).

## Payout Types

Payouts made to a bank account travel over the ACH network and support three speeds, set via the `payout_type` field on [Create Payout](/api/financial/create-payout):

- **`standard`** (default) — A standard ACH transfer. Settles over the standard multi-day ACH timeline.
- **`same_day`** — A same-day ACH transfer. Settles the same business day.
- **`instant`** — Sent over real-time payment rails instead of ACH batch processing, and typically settles within minutes. Requires the `payouts:instant` account setting to be enabled — see [Request Account Setting Access](#request-account-setting-access) below.

We will use a saved bank account to create a new payout. A verified bank account is the more reliable choice if you plan to send an `instant` payout — see [Instant Verification](/guides/payments/elements/accept-bank-account-payments#instant-verification).

### Request Account Setting Access

<Alert type="warning">This section only applies if you plan to use `instant` payouts. Skip it if you're using the default `standard` or `same_day` payout types.</Alert>

To use `instant` payouts, you will need to request access to the `payouts:instant` account setting type.

To do this, go to the [merchant portal](https://portal.publicsquare.com/settings/features) and click on the `Request this feature` button next to the `Instant Payouts` setting.
Alternatively, you can request access via the [API](/api/accounts/request-account-setting-access).

### Create a Payout

We need to make a call to [Create Payout](/api/financial/create-payout) endpoint. Omitting `payout_type` defaults to `standard`:

```shell showLineNumbers title="Create a Payout"
curl 'https://api.publicsquare.com/payouts' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "bank_account": "ba_7Ay5mcUXAxwrN6wQEQUVEHBCJ"
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

The amount is in cents. `1000` is $10.00.

<Alert type="warning">The IDEMPOTENCY-KEY header can be passed to protect against duplicate payouts being processed.</Alert>

### Create with Bank Account Details

If you have not saved the bank account yet, you can send its details with the payout. The API saves the bank account and sends the payout in the same request, so you do not need to call [Create Bank Account](/api/financial/create-bank-account) first.

Before you use `bank_account_details`:

- Your account must have the `payment-methods:bank-accounts:manual-creation` account setting. See [Request Account Setting Access](/guides/payments/elements/accept-bank-account-payments#request-account-setting-access).
- A restricted API key must have the `payment-method:write` permission in addition to `payout:write`. Secret keys have all permissions.

```shell showLineNumbers title="Create a Payout with Bank Account Details"
curl 'https://api.publicsquare.com/payouts' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "bank_account_details": {
      "account_holder_name": "John Doe",
      "account_holder_type": "individual",
      "account_type": "checking",
      "routing_number": "110000000",
      "account_number": "000123456789"
    }
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

- `bank_account_details` accepts the same fields as [Create Bank Account](/api/financial/create-bank-account).
- Include `account_holder_name` and `account_holder_type`. Some processors require them.
- You cannot combine `bank_account_details` with `bank_account` or `card`.
- If you omit the top-level `customer` or `billing_details`, the payout uses the `customer_id` and `billing_details` inside `bank_account_details`.
- Every [`payout_type`](#payout-types) works with `bank_account_details`, with the same requirements as a saved bank account.
- The response returns the saved bank account in `payment_method.bank_account`. Use its `id` as `bank_account` for later payouts.

<Alert type="warning">
  Send an `IDEMPOTENCY-KEY` with each request. If a request fails and you retry it with the same key, the payout uses the bank account that the first
  request saved. A retry with the same key and different bank account details returns a 400. Use a new key when you change the bank account details.
</Alert>

```json showLineNumbers title="Retry with different bank account details"
{
  "title": "Error",
  "status": 400,
  "detail": "'bank_account_details' differs from the request first sent with this IDEMPOTENCY-KEY."
}
```

### Create a Same-Day or Instant Payout

To use a faster payout type, set `payout_type` to `same_day` or `instant`:

```shell showLineNumbers title="Create an Instant Payout"
curl 'https://api.publicsquare.com/payouts' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  // highlight-next-line
  "payout_type": "instant",
  "payment_method": {
    "bank_account": "ba_7Ay5mcUXAxwrN6wQEQUVEHBCJ"
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

<Alert type="warning">If the `payouts:instant` account setting has not been enabled for your account, an `instant` payout request will fail. See [Request Account Setting Access](#request-account-setting-access) above. `same_day` payouts require no additional account setup.</Alert>

### Create with Payment Method's Billing Details

If you supplied the `billing_details` or [updated the bank account](/api/financial/update-bank-account), then you can omit the `billing_details` section when processing the payout:

```shell showLineNumbers title="Create a Payout with Payment Method"
curl 'https://api.publicsquare.com/payouts' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPOTENCY-KEY: 09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "bank_account": "ba_7Ay5mcUXAxwrN6wQEQUVEHBCJ"
  }
}'
```

Each of these request variants works the same way for `same_day` and `instant` payouts — just add the corresponding `payout_type` to the request body.

## Handling Declines

If a payout is declined, the response's `declined_reason` will contain the reason available at the time of the decline. When the receiving bank returns the payout, `declined_reason` contains the ACH return code and its description, for example `R03 - No Account/Unable to Locate Account`. The linked bank account's `status` may also change as a result of the decline. See [Bank Accounts](/concepts/bank-accounts#statuses).
